# Gap audit — Performance & PWA cluster

**From:** Performance/PWA specialist (audit seat)
**To:** Hue (project lead), for Dustin
**Date:** 2026-11-22
**Brief:** Audit the SPA redevelopment spec for performance and PWA best
practices that are MISSING or only PARTIAL. Profession's best practice
first, Dustin's house standards on top. Evidence graded honestly:
STRONG = primary-source documentation; MODERATE = documented mechanics
with limited/observed support; WEAK = field practice, contended.

**Spec read in full:** `spa-redevelopment-requirements-2026-11-22.md`,
`architecture-brief-claude-code.md`, `ux-structure-nadia.md`,
`ui-system-mina.md`, `seo-validation-bea.md`. The type foundation
(`type-foundation.md`) was consulted where the brief incorporates it by
reference (font loading). The spec was not credited for anything it
does not say; every "in spec?" cell quotes or pinpoints the nearest text.

## What the spec already does well (credited, not re-litigated)

- Complete-content prerendering (the single biggest LCP/TTFB lever on
  this stack), per-route code splitting, lazy below-fold modules.
- Font loading is genuinely specified — the type foundation sets
  subsetting, per-route caps (≤100 KB, ≤2 preloaded files), immutable
  font caching, metric-matched fallbacks, and SW precache of lead faces;
  the brief's non-negotiable 4 carries the caps.
- Mina's §4 makes CLS-on-state-change a measured build acceptance
  criterion, reserves space for every dynamic region, and flags
  keep-alive memory pressure on low-end phones for engineering.
- Nadia specifies the offline *posture* (shell + core visit facts
  readable offline, labelled with age; transactional submits queue) and
  the update *experience* (quiet notice, apply at a safe moment, never a
  forced reload); Mina draws both (`UpdateNotice`, `OfflineBanner`).
- Bea's cutover checks include a day-28 CWV field comparison against a
  pre-cutover baseline.

The gaps below are what remains after that credit. The pattern to
notice: **the spec is strong on intent and UX behaviour, and almost
entirely silent on numbers, cache policy, and enforcement.** On a
six-property program built by a bench, unspecified numbers do not stay
neutral — each property invents its own.

## Top 5 (for Hue)

1. **No numeric performance budgets, and no enforcement** (#1 + #2). "Minimal client JS" is the spec's only quantity; the bench gate is a green build, Quinn's gate is design. Add per-template budgets (JS/CSS/images/total) and a Lighthouse CI + bundle assertion step to the bench gate's repair loop.
2. **CWV targets exist but belong to nobody** (#3). Bea's LCP ≤ 2.5 s / INP ≤ 200 ms / CLS ≤ 0.1 sit inside an SEO content contract with no owner, no lab counterpart, and no named field instrument. Promote them into the requirements, add TTFB, name Cloudflare RUM as the field instrument of record.
3. **The R2 + CDN media layer has no pipeline contract** (#4). Tonight's decision rests on "where they earn their keep." Specify the transform contract (fixed width ladder, `format=auto`, quality), `srcset`/`sizes` per component slot, LCP-image `fetchpriority="high"` + sole preload, lazy everything else — before the in-flight architecture plan hardens without it.
4. **No caching strategy** (#5). "Edge-cached prerenders" with no HTML TTL/purge rule, no asset policy beyond fonts, and no edge caching of the identical-for-everyone public API GETs that currently hit single Durable Objects on every focus-return refetch.
5. **Service-worker policy is a mechanics question, not a policy** (#6). The brief asks the bench to verify *how* Vike does SWs; nobody has said what each property's worker must cache, what offline means for seeds/games/dashboard, how updates activate behind Mina's notice — or that the legacy /m PWA's worker must be deregistered at cutover before it strands installed visitors on the old tree.

*Runner-up, because it is nearly free: #7 — the RUM instrument already exists zone-wide; the spec just never assigns anyone to look at it after day 28.*
