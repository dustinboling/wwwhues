# Gap Audit — Accessibility Completeness & SPA Navigation Mechanics

Author: accessibility + SPA-UX-mechanics specialist (gap-audit brief).
Date: 2026-11-22. For: Hue. Cluster: accessibility beyond contrast, and
SPA navigation mechanics.

**Scope discipline.** Ada's `ada-rulings.md` is settled law and was NOT
re-audited: every contrast pair, the ground-following focus ring
(ruling 5), the line-2 ground table, and her seven frontier items stand
as she left them. Where a row below touches her frontier (items 4 and
6), it audits whether the *rest of the spec* picks the item up — it
does not re-open her ruling. Method: every candidate practice was
checked against the actual text of `ui-system-mina.md`,
`ux-structure-nadia.md`, `type-foundation.md`, and
`spa-redevelopment-requirements-2026-11-22.md` (grep + full reads of
the shell, form, motion, and live-update sections). The spec is not
credited for anything it does not say.

**The one-sentence finding:** the spec is a superb *visual* system —
states drawn, tokens ruled, in-place behaviour choreographed — but
the *programmatic* layer an SPA lives or dies on (where focus goes,
what gets announced, what things are called, how Back behaves) is
mostly unwritten, and in a six-property program unwritten means six
engineering teams invent six different answers.

## Credited — checked, present, NOT gaps (do not re-audit)

- **Dialog focus management** — Mina §3.4 Pattern B: focus traps inside, returns to the invoking control, Escape/backdrop dismiss, unsaved-changes protection. APG-conformant as written.
- **Sheet focus behaviour** — Mina §2.5: focus starts on the close control, closing returns focus to the More tab, Escape closes. (Its *history* behaviour is row 6; its focus behaviour is fine.)
- **Live region existence** — one persistent polite announcer, shell-level, with a "nothing steals focus" rule (Mina §4.3, Nadia §5). Rows 2 and 13 extend its charter; the component itself is right.
- **Filter history** — Nadia §2/§5: filter state in the URL query via history, "one entry per deliberate change," Back/Forward walk filter states in place. Specified.
- **Tab-state preservation & scroll** — Nadia §3, Mina §4.4. Specified in detail (row 7 covers *routes*, not tabs).
- **Media Session integration** — Nadia §4.4 (lock-screen/headphone controls, state survives backgrounding). Present.
- **Hostile-form rules** — data never cleared on failure, Postel input handling, offline queueing with pending state (Nadia §4.1–4.2, Mina §3.4/§4.4). Present.
- **Focus contrast & the double-signal ring** — Ada ruling 5. Settled; not re-audited.
- **Skeleton reduced-motion behaviour** — static under reduced motion (Mina §4.2/§6). Present.

## Top 5 (for Hue)

1. **Route-transition focus management (row 1, Critical)** — the spec never says where focus goes on a route change. This is the single behaviour that decides whether the SPA is usable with a screen reader or a keyboard, and it is absent from all four documents.
2. **Route-change announcement + title update (row 2, High)** — the LiveRegion exists but its charter stops at dynamic results; navigation — the largest content change there is — announces through nothing, and the document title never changes in-session.
3. **Skip link + landmarks (row 3, High)** — a Level A criterion with zero spec presence in any of the six shells; cheap to fix now, expensive to retrofit per property.
4. **Programmatic state semantics (row 5, High)** — every visual state is drawn and almost none are named (`aria-current`, `aria-expanded`, chip/segmented semantics, dialog roles). Six builds will invent six dialects unless §6 gains a semantics column.
5. **Games accessibility annex (row 12, High for Lightning)** — keyboard operation, timing limits, and flash safety are wholly unspecified for the six games + This or That that Dustin has explicitly put inside this program; the Lightning Round is timed and effect-heavy, and its build ticket currently carries no accessibility requirements at all.
