source tonight: `~/workspace/huesflowers-live` (site + workers),

## Cluster 2 — Data / API practices

The spec is detailed about *visual* data behaviour and silent about the
data layer underneath it. Nadia's live-data table (`ux-structure-nadia.md`,
§5.4-adjacent) does specify *refresh triggers* per surface ("Refetch on
focus return", "Recompute on visibility return and on the hour boundary",
"submit optimistically with honest reversal on failure") — that is the
nearest thing to a data specification in the program, and it is still
behaviour, not a layer. Everything below is about what that behaviour
needs to stand on.

| 2.1 | **Client data-fetching standard** (caching, deduping, stale-while-revalidate, retries) | **Missing.** Spec-wide sweep: zero mentions of a query/caching library, cache policy, deduping rule, stale windows, or retry policy. The phrase "stale-while-revalidate" appears once — as a *visual* pattern name: "Stale-while-revalidate is the pattern: show the last true data, refresh quietly, wash what changed" (`ui-system-mina.md:713`). No data layer is named to implement it. `npm run build` — verified firsthand in
`wwwhues/.github/workflows/muse-code.yml` ("Gate: `npm run build` passed";
gate step = `npm ci` + `npm run build`, with the 3-repair-turn loop). The
wwwhues `package.json` has **no** test, typecheck, or verify script (scripts:
dev / build / start / lint / preview / deploy / upload / cf-typegen). The
program's own repos are inconsistent: **seeds-hues v2 already has**
`verify` = lint + `tsc --noEmit` + `vitest run`, plus an `acceptance`
script. The spec never picks a floor — so the new stack can land anywhere
between the two. (The general gate enumeration is `gaps-security-ops.md`
§10; performance-budget enforcement is `gaps-performance-pwa.md` #1–#3.
This cluster is the *testing* depth: what to test, with what tool, on
which flow.)

## Combined top 5

1. **The gate cannot catch what the standard forbids (3.1 + 3.2, Critical).** The pipeline's only automated gate is `npm run build`, and the wwwhues repo has no test/typecheck script at all — while seeds already runs `verify` = lint + `tsc --noEmit` + vitest. Worse, the same gate command gets weaker at the stack change: `next build` type-checks, Vite's build does not. The "strictly typed" standard in the brief is currently unenforceable. Fix: adopt seeds' `verify` as the per-repo gate floor before the first build task is dispatched.
2. **Structured-data parity is un-inventoried and its one automated guard is un-carried (1.1 + 1.2, Critical).** No property has a required JSON-LD inventory, and seeds' `assertNoProhibitedJsonLd` — the only automated enforcement of Dustin's no-prices rule — is never mentioned. A bench rebuild can silently drop SearchAction/BreadcrumbList or emit a priced Product block and pass every gate. Fix: a per-property inventory file diffed at Quinn's gate, and the guard ported into the shared package.
3. **The data layer is unspecified end-to-end (2.1 + 2.2, Critical/Important).** No client fetching standard, no cache/dedupe/stale policy, and the hues workers emit no Cache-Control or ETag anywhere — while seeds already ships both the query-layer precedent and ETag/304 helpers. Nadia's "instant tab returns" and Mina's "never skeleton" promises rest on nothing. Fix: name one query layer with written defaults, and add a per-API response-caching table as additive headers.
4. **Filter and pagination URL rules are missing (1.5 + 1.6, Important).** Facets and sort parameters are specified as UI but never as crawl policy; paginated lists have no crawlable-structure requirement. On an 812-page directory, the default build burns crawl budget on near-infinite filter combinations and can strand deep pages behind button-only paging. Fix: a parameter policy table per property and prerendered paginated URLs with self-canonicals.
5. **The media-domain move has no image-SEO half (1.4, Important).** The R2+CDN decision changes every image URL on every property, but the spec covers only hosting and delivery. Google's image guidance — descriptive filenames, alt text, cross-domain image sitemaps — is the checklist for exactly this move, and the media subdomain needs GSC verification before the first cutover. Fix: filename map, old→new image redirects, image sitemap entries, media-subdomain verification, alt text as a kit requirement.
